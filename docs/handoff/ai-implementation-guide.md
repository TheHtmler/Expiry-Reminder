## 3. 实施计划的使用方式

实施计划中的每个任务是独立评审单元。执行规则：

1. 只处理当前任务列出的文件。
2. 保持任务中定义的接口名称和字段一致。
3. 先运行失败测试，再添加实现。
4. 每一步完成后勾选对应复选框。
5. 运行任务指定的测试和验证命令。
6. 输出变更摘要、测试结果和剩余风险。
7. 得到项目所有者确认后再提交。

如果发现设计与平台实际能力冲突：

1. 停止扩大实现。
2. 记录官方文档链接和具体冲突。
3. 给出不超过三个可行方案及影响。
4. 等待项目所有者选择。
5. 同步修改设计、计划和代码。

## 4. 不能自行改变的产品决策

- 首页采用提醒优先布局。
- 底部导航为首页、物品、提醒、我的。
- 扫码录入是全局快捷入口。
- 相同商品每次录入仍是独立记录。
- 只有条码、到期日和位置完全相同时才提示合并数量。
- 默认提醒家庭内所有有效成员。
- 普通成员可新增、编辑、调整数量和处理物品。
- 普通成员不能移除成员、解散家庭或批量移动物品。
- 分类支持自定义与排序，但不支持动态自定义字段。
- 微信订阅消息失败时，提醒中心仍必须完整可用。
- 数据与服务端接口需要为未来 App 保留复用边界。

## 5. 外部配置

以下值不会存储在 Git 中，需要在实施对应任务时由项目所有者在本地或云控制台配置：

- `CLOUDBASE_ENV_ID`
- `WECHAT_REMINDER_TEMPLATE_ID`
- `TENCENTCLOUD_SECRET_ID`
- `TENCENTCLOUD_SECRET_KEY`

这些配置缺失时，相关任务应提供清晰的本地错误信息和测试替身，但不得写入虚假的
生产成功逻辑。

CloudBase 开发与生产环境必须隔离。开发阶段优先使用免费体验环境；是否升级套餐由
真实调用量、云函数超时和上线准备情况决定。

## 6. 数据与权限重点

任何接受 `householdId` 的服务端接口都必须：

1. 从可信登录上下文获取当前用户。
2. 查询 `household_members`。
3. 验证成员状态为 `active`。
4. 对管理员操作验证角色为 `admin`。
5. 在查询或更新条件中再次包含 `householdId`。

数量调整使用原子更新或乐观锁。创建操作使用 `requestId` 保证幂等。提醒任务使用
`householdId:itemEventId:localDate` 唯一键去重。

## 7. 验证重点

除单元测试外，至少覆盖：

- 两名家庭成员共享和同步数据。
- 普通成员越权操作失败。
- 同时减少最后一件物品时数量不会小于零。
- 断网重试不会重复创建物品。
- OCR 低置信度不会自动保存。
- 月末、年末和闰年日期正确。
- 微信订阅消息拒绝或失败时提醒中心仍可用。
- 被移除成员立即失去家庭数据访问权限。
- 凭证图片不能跨家庭访问。

## 8. 完成交接时的输出

每个任务完成后，向项目所有者提供：

- 实际修改的文件。
- 已实现的行为。
- 执行过的完整验证命令。
- 测试数量与结果。
- 需要在微信或腾讯云控制台完成的人工配置。
- 下一任务名称。

不要只回复“已完成”，也不要在验证失败时声称功能可用。
