# 到期咯核心流程 CloudBase 接通设计

## 目标

在开发环境 `cloud1-d6ga4b3yb70ea3b1c` 跑通以下真实数据链路：

1. 微信用户首次进入小程序。
2. 服务端自动创建“我的家”和八个默认分类。
3. 用户手动录入物品。
4. 用户查看物品详情。
5. 用户将数量减至零，物品自动标记为已用完。

本阶段不实现扫码、OCR、提醒中心或订阅消息，也不改版 UI。

## 已确认现状

- 本地 20 个测试文件、49 项测试全部通过。
- `npm run typecheck` 与 `npm run build` 通过。
- CloudBase 环境存在，`api` 云函数状态为 `Active`。
- 云端 `api` 与本地构建产物 SHA-256 不一致。
- 云端版本缺少自动创建集合与最新会话竞态修复。
- 云端运行时为 Node.js 16.13，超时时间为 CloudBase 默认的 3 秒。
- 微信开发者工具服务端口已开启，端口为 `16280`。

## 接通方案

### 云函数配置

将开发环境 `api` 云函数超时时间从 3 秒调整为 10 秒。首次初始化需要并行创建九个
集合，并创建用户、家庭、管理员成员与默认分类；10 秒为开发环境联调提供足够余量。

本阶段保持现有 Node.js 16.13 运行时，避免同时引入运行时迁移变量。当前构建产物不依赖
Node.js 18 专属 API；核心流程通过后再单独评估运行时升级。

### 部署与校验

使用微信开发者工具 CLI 将本地 `cloudfunctions/api` 部署到指定开发环境，并选择云端
安装 `wx-server-sdk` 依赖。部署后重新查询函数状态、下载云端代码并与本地构建产物计算
SHA-256；只有哈希一致且函数状态为 `Active` 才进入真实调用。

### 首次初始化

首次 `session.bootstrap` 请求若遇到集合不存在错误，云函数幂等创建以下集合并重试：

- `users`
- `households`
- `household_members`
- `household_invites`
- `idempotency_keys`
- `categories`
- `locations`
- `items`
- `item_events`

随后服务端在事务内创建“我的家”、当前用户管理员成员和八个默认分类。重复请求不得
创建第二个默认家庭。

### 数据安全

自动建集合只解决开发环境可运行性，不替代正式配置。核心流程通过后，在 CloudBase
控制台按 `infra/cloudbase/indexes.json` 配置唯一索引，并应用
`infra/cloudbase/database.rules.json` 的默认拒绝规则。客户端始终只调用云函数，不直接
写业务集合。

## 错误处理

- 部署失败：保留现有云端版本，记录 CLI 错误，不继续真实调用。
- 首次调用超时：先查看云函数日志，确认停留层级，再决定调整配置或拆分初始化。
- 集合创建失败：不清空环境，不物理删除已存在集合，只修复当前失败项。
- 默认家庭创建失败：依赖事务回滚，重试同一会话初始化。
- 录入或数量更新失败：保留页面错误信息与云函数日志，禁止用模拟成功响应绕过。

## 验收

- 云端 `api` 与本地构建产物哈希一致。
- 首次登录后只有一个“我的家”。
- 默认分类恰好八个。
- 新建物品后首页、列表和详情读取同一真实记录。
- 数量从 1 减至 0 后，状态为已用完，版本号递增且数量不为负数。
- 本地测试、类型检查和构建保持通过。
- 实际结果同步到 `docs/handoff/implementation-progress.md`。
